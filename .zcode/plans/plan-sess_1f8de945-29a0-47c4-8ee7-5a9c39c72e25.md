# HFusionHub 后续优化方案（第十五轮规划）+ P0 批次实施

## 探索结论（方案依据）

三路深度探索（文档路线图 / Java 后端 / Python AI）发现：项目 P0/P1/P2 十四轮已交付，但存在**真实缺陷**（非单纯优化），其中最严重的是刚上架的容器插件经 agent 链路实际不可用。已确认的顶层问题：

1. **容器插件 agent 链路损坏**：`registry.py:875` 在异步方法里同步调 `execute_plugin_tool`；container 模式下 `sandbox_runner.py:390-404` 在已有事件循环的线程里 `new_event_loop().run_until_complete()` → RuntimeError 被 except 吞掉，静默返回 `container_runner_unavailable`（fail-closed 所以无报错）。P2-3 的 e2e 只验证了 runner 直连，没覆盖 agent 链路。
2. **跨租户语料缓存泄漏**：`milvus_store.py:188-219` BM25/citation 语料缓存 key 不含 tenant_id，双租户并发读时 B 租户拿到 A 租户语料。
3. **OpenAPI key 解析租户 bug**：`/openapi/**` 不走租户拦截器，`OpenApiServiceImpl.resolvePublishedApp:162-178` 查询时被行拦截器默认填 `tenant_id=1`，非 1 租户的 API key 全部 401。
4. **流式聊天绕过输出守卫**：`chat.py:363-366` 明确 SSE 不做 `guard_model_output`，非流式被拦的内容可从流式通道流出。
5. **插件沙箱 fail-open**：manifest 无 sandbox 段 = 无网络/文件限制（`sandbox_runner.py:284-287`）；Windows 下资源限制静默跳过。
6. **plugin-runner 事件循环阻塞 + 结果解析 fail-open**：async 处理器内同步 Docker SDK 调用；末行非 JSON 时 `success=True` 返回 raw_output。
7. **内部插件审计租户错标**：`InternalPluginController.receiveAuditLogs:89-130` 无 TenantContext，行全落 tenant_id=1。
8. **密钥与暴露面**：`MODEL_CREDENTIAL_ENCRYPTION_KEY` 回退复用 PYTHON_AI_INTERNAL_TOKEN（轮换一个毁掉全部已存用户 key）；CORS 默认通配源+携带凭据；actuator 认证策略未定义。

同时确认：项目已有 `docs/OPTIMIZATION_PLAN.md`（P0–P5 完成，遗留 Java 统一缓存 §1.9 等少数项），文档层存在测试计数/Flyway 版本/CI_GATES 分支保护矛盾等 10 处失真；`TODO.md` 有 5 项生产上线阻断安全项未勾选。做得好的部分（租户隔离设计、HMAC 回调、幂等账本、模型网关熔断、评测门禁）保持不动。
